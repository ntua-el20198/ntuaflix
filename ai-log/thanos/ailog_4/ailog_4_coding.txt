If you want to access the textarea from within the event listener function but it's not directly accessible because it's created within another function (createCommentBox in your case), you can use a closure to capture the textarea variable. Here's how you can do it: 

function createCommentBox() {
    const commentBox = document.createElement('div');
    const textarea = document.createElement('textarea');
    const submitButton = document.createElement('button');
    
    submitButton.textContent = 'Submit';

    submitButton.addEventListener('click', function() {
        // Call a function and pass the textarea
        yourFunction(textarea);
    });

    commentBox.appendChild(textarea);
    commentBox.appendChild(submitButton);

    document.body.appendChild(commentBox);
}

function yourFunction(textarea) {
    // Access the textarea here
    console.log(textarea.value);
}

// Call createCommentBox to create the comment box
createCommentBox();

In general, it's often considered good practice to modularize your code and keep functions focused on specific tasks. This can make your code more readable, maintainable, and easier to debug.

However, there are cases where it might be appropriate to encapsulate related functionality within a single function, especially if that functionality is tightly coupled and unlikely to be reused elsewhere. In the case of creating a comment box and handling its submission, if this is a standalone component or behavior specific to a certain part of your application, it might be acceptable to have it within a single function.

That said, if you anticipate needing similar functionality elsewhere in your codebase or if the createCommentBox function becomes overly complex, it may be a good idea to split it into smaller, more modular functions. This can help promote code reusability and maintainability in the long run.

Ultimately, the decision depends on the specific requirements and architecture of your application, as well as your own preferences and coding style.
